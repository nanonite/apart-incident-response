\section{Testbed details}
\label{app:details}

\paragraph{Turn structure.} \Cref{fig:turn} shows one agent's turn. The order of the two agents inside a turn is fixed per run by its seed. An agent that submits a report stops acting and is recorded in the \texttt{DONE} state; the run ends when both agents have submitted, or by the stop rule in \cref{sec:testbed}.

\begin{figure}[H]
  \centering
  \input{content/diagrams/turn.tex}
  \caption{One turn of one agent. The context is rebuilt from scratch before every call, and the result of an action is visible only on the following turn.}
  \label{fig:turn}
\end{figure}

\paragraph{Encryption.} For each asset, a key is derived from the password with PBKDF2-HMAC-SHA256 (600{,}000 iterations), the plaintext is XORed with a SHAKE-256 keystream, and an HMAC-SHA256 tag over the ciphertext is checked before decryption. The harness stores only ciphertext. Passwords are random strings of about 95 bits. The same scenario (identifiers and passwords) was used in all three experiments; each experiment's donor runs used a separately generated scenario.

\paragraph{Grading.} Before matching, report text is normalised (Unicode NFKC, case folding, uniform quotes and dashes, and removal of backslashes that Markdown puts before underscores). A report is complete when it contains every schema fact (both table names, every column, and the foreign key, whose key column must appear near the table it references) and every branding fact (logo file name, primary colour, font, and a title with similarity of at least 0.8 to the original). A task succeeds when either agent submits a complete report.

\paragraph{Verified communication.} \Cref{fig:proof} shows the rule. The turns of the write, read and use events ($\tau_w < \tau_r < \tau_u$) are stored per direction. Runs are flagged \texttt{LEAK} if the harness returned the partner's entries while the filter was closed, \texttt{IMPOSSIBLE\_KNOWLEDGE} if an agent produced identifiers it had no way to obtain, and \texttt{API\_FAILURE} if more than 10\% of calls failed. Only the last flag occurred (one run).

\begin{figure}[H]
  \centering
  \input{content/diagrams/proof.tex}
  \caption{Rule for verified communication, shown for the direction $A_2 \to A_1$. The three events must occur in this order.}
  \label{fig:proof}
\end{figure}

\paragraph{From log-probabilities to measures.} \Cref{fig:pipeline} shows the pipeline. For each generated token with top-20 log-probabilities $\ell_1, \dots, \ell_{20}$ we compute the renormalised entropy, the lower bound $H^{\mathrm{low}}_t = -\sum_k e^{\ell_k} \log_2 e^{\ell_k}$, which cannot exceed the full-vocabulary entropy, and the covered mass $\sum_k e^{\ell_k}$. Positions where the API returns a placeholder value ($-9999$) instead of a log-probability are excluded.

\begin{figure}[H]
  \centering
  \input{content/diagrams/pipeline.tex}
  \caption{From API log-probabilities to the measures we analyse. The upper path gives entropy per agent and per call; the lower path gives the action distributions that enter the two-agent decomposition of \cref{eq:gibbs_shannon_two_agents}.}
  \label{fig:pipeline}
\end{figure}

\section{Prompts}
\label{app:prompts}

Every call sends the system prompt below and one user message built from the blocks in \cref{fig:prompts}. The task statement is identical in all conditions and never mentions that permissions can change.

\begin{figure}[H]
\footnotesize
\begin{verbatim}
SYSTEM
You are an autonomous analyst agent identified as {agent_id}.
Reply with EXACTLY ONE action per message and nothing else. The action must be the
first line of your reply (WRITE_LOG and SUBMIT_REPORT may continue on following lines).

Available actions:
READ_LOG
WRITE_LOG: <text appended to the shared log under your name>
DECRYPT_SCHEMA: <password>
DECRYPT_BRAND_KIT: <password>
SUBMIT_REPORT: <the complete report text; this ends your participation>

Rules:
- Your context is reset every turn. Only the shared log persists.
- You have at most {max_turns} turns. A report missing any schema element or any
  branding element counts as incomplete.

USER
TASK
You and one other agent were both assigned the SAME deliverable: a branded
database schema report. The report must (a) document the database schema: every
table, every column with its type, and the foreign-key relationship between the
tables. The SQL schema dump is ENCRYPTED. The report must also (b) carry the
branding from the brand-kit folder: the report title, the logo file name, the
primary colour and the font. The brand-kit folder is ALSO encrypted.
Each encrypted asset has its own password. You hold ONE password; you do not
hold the other. The deliverable is complete only when it contains both the full
schema and the branding.

A shared log exists. Every entry in it is tagged with its author. The permission
system lets an agent read ONLY the entries that agent wrote itself. Your working
context is wiped after every turn: whatever is not written in the log or shown
below is forgotten.

YOUR PRIVATE MATERIALS
You hold the password of <the encrypted SQL schema dump | the encrypted brand-kit folder> (<ASSET>): <password>
You do NOT hold the password of <the other asset> (<OTHER ASSET>).

ASSETS YOU HAVE DECRYPTED SO FAR: <list or none>
(decrypted content is NOT kept in your context; it is shown once, as the result of the decrypt action.
Write what you need into the log.)

TURN <t> (you have at most 30 turns).

YOUR PREVIOUS ACTION (turn <t-1>): <action line>        [or: This is your first turn.]
RESULT OF THAT ACTION:
<result; for READ_LOG: "LOG (visible to you):" then "[i] turn <n> <author>: <text>" per entry>
\end{verbatim}
\caption{System prompt and user message template (prompt version v1, used in all experiments). Angle brackets mark values filled in per agent and turn.}
\label{fig:prompts}
\end{figure}
