\subsection{Entropy of agents and of the system}
\label{sec:entropy}

Shannon entropy measures how uncertain the outcome of a random variable is \parencite{shannon1948mathematical}. For a variable $X$ with outcomes $x_1, \ldots, x_n$,
\begin{equation}
  H(X) = - \sum_{i=1}^{n} p(x_i) \log_2 p(x_i),
  \label{eq:shannon}
\end{equation}
which is zero when the outcome is certain and reaches $\log_2 n$ bits when all outcomes are equally likely \parencite{cover2006elements}. A language model gives us such a distribution at every step. From the logits $z_t$ it produces for the next token, given the context $x_{<t}$ and a sampling temperature $T$,
\begin{equation}
  p(v \mid x_{<t}) = \frac{\exp\left(z_{t,v} / T\right)}{\sum_{u \in V} \exp\left(z_{t,u} / T\right)},
  \label{eq:softmax}
\end{equation}
and the entropy of that distribution,
\begin{equation}
  H_t = - \sum_{v \in V} p(v \mid x_{<t}) \log_2 p(v \mid x_{<t}),
  \label{eq:token_entropy}
\end{equation}
is the model's uncertainty about what comes next. This is \emph{predictive} entropy \parencite{malinin2021uncertainty}. \emph{Semantic} entropy instead samples many full answers, groups them by meaning and measures uncertainty over those groups, so that rewording does not count \parencite{kuhn2023semantic, shannon_hallucination}. We use predictive entropy, because it is available from a single generation and because a change in wording is part of what we expect foreign text to cause.

These quantities describe one agent. For a system of $n$ agents with outputs $X_1, \ldots, X_n$, the joint entropy is
\begin{equation}
  H(X_1, \ldots, X_n) = \sum_{i=1}^{n} H(X_i) - TC(X_1; \ldots; X_n),
  \label{eq:mas_entropy}
\end{equation}
where the total correlation $TC$ measures how much the agents depend on each other and is zero only when they are independent \parencite{watanabe1960}. For two agents it reduces to the mutual information $I(X_1; X_2)$. Our original hypothesis was that agents who communicate become coupled, so $I$ should rise when a hidden channel opens. To estimate it we let $X_i$ be the action agent $i$ takes at a given turn. The two agents are sampled in separate calls, so within one run they are independent given their contexts, and any dependence can only show up across runs. For each model, condition and turn we therefore pool the action distributions $q^r_i$ of the $N$ runs, $p(a_1, a_2) = \frac{1}{N} \sum_r q^r_1(a_1)\, q^r_2(a_2)$, and compare the resulting $I$ with a null in which agents from different runs are paired at random. Agents that share a model and a task behave alike without talking, and this null removes that part.

\subsection{A testbed built from the incident}
\label{sec:testbed}

We rebuilt the incident as a small testbed: two sandboxed agents, each holding one password to a task neither can finish alone, and a shared log that stays closed, opens mid-task (real communication) or delivers foreign noise (placebo). \Cref{fig:architecture} shows the design, and each part of it stands for something in the incident.

They share an append-only log in which every entry carries its author. Writes always go to the log; reads pass through a filter that returns only the reader's own entries. In the switch condition the filter returns the entries of both agents from turn $t_s = 8$. In the placebo condition it keeps the restriction but adds entries from an unrelated donor run, labelled as the other agent's.}
  \label{fig:architecture}
\end{figure*}

At the top is the task $T$, the same for both agents: a report on a database schema that must list every table, column and foreign key and carry the title, logo, colour and font of a brand kit. This synthetic task models credential separation and information transfer, without live exploitation or production targets. Neither agent initially holds both passwords. Report wording can vary, but completeness is checked against fixed asset facts; creative quality is not scored. This gives us verifiable information use before extending the study to open-ended collaboration. Each agent's context is rebuilt every turn from the task, its private material and its previous action and result; the log is its only durable memory.

Below each agent is a password and an encrypted asset. $A_1$ can open the brand kit and $A_2$ the schema, just as agents in the incident held credentials they had been given legitimately. The encryption is real (PBKDF2 key derivation, a SHAKE-256 keystream and an HMAC tag), so a wrong password returns nothing. Passwords and every identifier inside the assets are random strings. If one of them appears in an agent's output, it came either from decrypting the asset or from the other agent, never from training data, and this is what makes communication provable.

In the middle is the shared log, our version of the package mirror. It is append-only and every entry is tagged with its author. Agents write with \texttt{WRITE\_LOG} and read with \texttt{READ\_LOG}; the only other actions are password-checked decryption and \texttt{SUBMIT\_REPORT}. No agent shell, file writes or arbitrary network requests are exposed. Every read passes through a filter. The task continues to state that agents can read only their own entries, even after the filter changes; the opening is not announced.

Here, \emph{foreign text} means peer or donor log entries returned to an agent, outside its own interaction history. It excludes the fixed task, private material and permitted decryption results. The term describes provenance relative to intended isolation, not maliciousness or novel wording: even useful, benign text can cross that boundary. Availability at turn 8, delivery through a read, and subsequent use are distinct events; the checker verifies use separately (\cref{sec:protocol}).

The two boxes under the log are what we change. In the switch condition, the filter opens at turn $t_s = 8$ and reads return both agents' entries, including earlier ones. In the placebo condition, the filter stays closed, but from turn 8 reads also return donor entries from an unrelated scenario of the same model, labelled as the peer's. Useful information here means valid passwords or required asset facts for the current task; donor entries contain neither. The placebo shares the log format and author labels, although entry counts, lengths and actual read times need not match. This control tests whether entropy distinguishes useful peer information from task-irrelevant foreign text. In the base condition, the filter never opens. \Cref{fig:conditions} shows the visibility rules.

For task extensions, the repository also provides a researcher dashboard for selecting tasks, inspecting supplied contexts and shared messages, and exporting traces. Its checkpoint protocol is separate from the turn-based harness used for these results. Published configurations, synthetic traces and checker outputs support offline review without laboratory-network access; they do not certify production containment.

\subsection{Protocol and analysis}
\label{sec:protocol}

A run proceeds in turns, with each agent taking one action per turn. It stops at turn 20 if one agent has submitted a complete report, otherwise at the first complete report or at turn 30. A deterministic checker grades every report against the asset facts and marks communication from $A_i$ to $A_j$ as verified only if three things happen in order: $A_i$ writes its password or identifiers to the log, a read by $A_j$ returns that entry, and $A_j$ then uses it to decrypt $A_i$'s asset or writes identifiers it could not have obtained otherwise. No language model is involved in grading. Runs are discarded if more than 10\% of API calls fail. The team's Pi runtime implements the same board design for sandboxed coding agents; for this study we used a minimal harness that calls the models directly, which gives us the token log-probabilities we need.

We ran three models from different families, gpt-4o-mini, Llama 3.3 70B and Qwen3 235B, through OpenRouter. Each was pinned to a single provider (OpenAI, Novita and Google Vertex), because providers serving the same model return different probabilities. Every call requested the log-probabilities of the 20 most likely tokens at each position. We repeated the whole experiment at temperatures 1, 0.5 and 0, with 20 runs per model and condition, 540 runs in total at a cost of US\$4.18. Temperature decides how much of an agent's behaviour is sampling noise, and we wanted to know whether a signal hidden by noise at $T = 1$ would appear when decoding was more deterministic. Vertex returns log-probabilities after temperature scaling, so for Qwen at $T = 0.5$ we undid the scaling before computing entropy, and all entropies refer to the model's unscaled distribution. Before each experiment, every model had to finish the task in at least half of 10 switch runs with the shared prompt, and all of them did.

For every call we compute three measures from the returned log-probabilities, renormalised over the top 20 tokens. \emph{Token entropy} is the mean of \cref{eq:token_entropy} over the call. \emph{Adjusted entropy} removes the part explained by what the agent was doing, since a fixed \texttt{READ\_LOG} and a long free-text report differ in entropy for reasons unrelated to the log; it is the residual of a regression on action type and response length. \emph{Decision entropy} is the uncertainty about the next action itself, read at the first token of the reply by assigning each candidate token to the action it starts to spell.

A monitor watches one run as it unfolds, so the run is our unit of analysis. For each run we take the mean of a measure over turns 8 to 20 minus its mean over turns 1 to 7, which compares the run with its own past. We then compare these changes between conditions with permutation tests, bootstrap confidence intervals and the AUC, correcting for multiple comparisons with the Holm method, and we check the results with a call-level mixed model. Finally, to see how the signal would behave as an online alarm, we run a CUSUM detector \parencite{page1954cusum} on each run's adjusted entropy, with its threshold set so that 5\% of base runs raise a false alarm.
